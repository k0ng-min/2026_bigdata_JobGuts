# 역할 분담 및 공통 운영 규칙

## 역할

| 역할 | 주 담당 디렉터리 | 책임 | 인계 산출물 |
| --- | --- | --- | --- |
| 데이터 확보 및 전처리 | `src/ingestion`, `configs` | 파일 선정, 스키마, 중복·결측·범위 처리 | 확정 공고 식별자, 품질 요약, 분석용 기술 목록 |
| 기술명 정규화 및 검증 | `src/normalization` | 기술 사전, 표기 통일, 원문 표본 검증 | 사전 버전, 정규화 기술 배열, 변환·예외 기록 |
| Apriori 및 연관규칙 분석 | `src/analysis` | 트랜잭션, 규칙, 지표·세그먼트 비교 | 규칙 테이블, 파라미터, 재현 실험 결과 |
| 서비스 및 GLM 준비 | `src/retrieval`, `src/service`, `src/llm` | 필터·조회·근거 제시, UI/API, GLM 경계 설계 | 질의/응답 스키마, mock, 통합 시나리오 |

## 공통 계약

- 공고 식별자, 원문, 원본·정규화 기술 목록, 직무, 경력 원문·구간, 검토 상태를 손실 없이 보존한다.
- 직무와 경력은 Apriori itemset에 포함하지 않는다.
- 분석 결과에는 데이터·사전 버전, 세그먼트 정의, 최소 support와 confidence를 포함한다.
- 서비스는 분석 결과를 직접 재계산하지 않고 조회 모듈을 통해 읽는다.
- `src/llm`은 인터페이스와 mock만 둔다. 실제 GLM SDK·API·키·네트워크 호출은 최종 통합까지 보류한다.

## Git 운영

- 역할 디렉터리 중심의 작고 검토 가능한 커밋을 만든다.
- 커밋 전 테스트와 포맷 검사를 실행한다.
- 데이터 원본, API 키, 개인 정보, 대용량 중간 파일은 커밋하지 않는다.
- 주차 종료 시 `artifacts/` 요약과 주차 문서의 실제 결과·문제점·다음 작업을 갱신한다.
